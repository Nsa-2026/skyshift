# contracts/dots.md: the dot table, forced photometry and derived tables (v4)

Owner: P1. Written by pipeline/, read by validation scripts and the suspects export.
Units: degrees, arcsec, µm, µJy, MJD (UTC).

## dots: one row per detected point in one photo

One Parquet file per photo in `gs://nasa-glazing-data/dots/`. Its existence marks the photo done;
skip it on restart. No job list, no locks, no tiles.
File name `dots/<obs_id>D<detector>.parquet`, e.g. `dots/2025W18_1B_0074_2D1.parquet`.

**Folders (15 Nov).** sep's `deblend_cont` is a pipeline setting: `DOTS_DEBLEND_CONT` = 0.005 for the sky run (`dots/`).
The zones of `DOTS_FINE_ZONES` (t_rdra, t_barnard, t_rwaur, t_epsindib, t_wise0855) use `DOTS_FINE_DEBLEND_CONT` = 1e-4,
which splits a star off a much brighter star's glow (R Dra D4: 3 of 4 Gaia neighbours at 92–162″, none at 0.005). Their
photos also lie in ecliptic zones and files are never rewritten, so another value has its own folder,
`dots_deblend<value>/` (`dots_deblend1e-4/`), with the same file names, columns and rules; nothing in `dots/` changes.
A zone's derived tables point into the folder its `link` read: `results/<zone>/summary.json` `steps.link.dots_dir`
(absent = `dots`). Every reader of a zone's dot files (pipeline steps after link, candidates, shape, server
measured.py) reads that folder.

**Fine detection v2 (15 Nov night).** The folder name is built from every setting that differs from the sky run's:
`dots[_deblend<value>][_cp<clean_param>][_g<guard px>][_psf]` (config.dots_dir_for). The `DOTS_FINE_ZONES` now use
`dots_deblend1e-4_cp3_g6_psf/`; `dots_deblend1e-4/` (plain 1e-4) stays as written and is read only by a zone whose
link recorded it. v2 is three changes. (1) sep `clean_param` 3 (sky run: 1, sep's default): fewer faint stars are
cleaned into a brighter one's wings. (2) Saturation guard: a dot that the sky run's setting (0.005, clean_param 1) does
not also find within 1 px is dropped when it lies within `DETECT_SAT_GUARD_PX` (6 px) of an OVERFLOW or NONLINEAR pixel:
those are pieces of a saturated star's wings, not stars. (3) ePSF second pass: the ePSF of every unsaturated dot with
S/N ≥ 10 is subtracted, sep runs again on the residual within 6 px of those dots, and a new dot is kept when it is
> 1 px from every dot, has S/N ≥ 5 on the residual, passes a mirror test (the residual at its point reflection through
the dot it sits beside is < 0.5 × its flux, ≥ 3σ less) and passes the saturation guard. Such dots have `sep_flag` bit
0x200 and are measured on the residual (IMAGE minus the subtracted ePSF models): x, y, flux, snr, shape, ePSF flux and
position, apertures. The bright neighbour's own row is measured on IMAGE as before, so it still includes the
companion's light. Rows stay sorted by flux_ujy, brightest first. Test on 43 hunt photos (D1–D6): Gaia pairs 2–3 px
found 9% → 81%, known asteroids within 6 px of a brighter star 4 → 14 of 17; estimated fake dots per photo (~21,900
dots) ~12 with clean_param 3 and the second pass, up to ~50 with 1e-4 as well, mostly near G < 10 stars.

**Glow model (16 Nov).** Around a saturated or very bright star the wings and halo stay above the sky to ~25–30 px
(150–180″), and detection cut them into "stars" with nothing behind them (Barnard's Star, stack-only sources per
arcmin² per epoch: ~21 within 30″, 5–7 at 30–120″, 1.4 at 120–180″, against a flat Gaia density). The glow model
(skyshift_core.glow) takes it out before detection; columns, units and rules of the dot table do not change. Per photo:
the stars to model are every saturated core (a masked blob holding OVERFLOW/NONLINEAR; from 16 Nov evening only masked
pixels within 6 px of an OVERFLOW/NONLINEAR pixel belong to it, `GLOW_CORE_REACH_PX`: a STREAK through one saturated
pixel had made a 135 px "core" and dropped every dot within ~840″ as its pieces) and every peak ≥ 300 × the pixel
noise, at most 400, brightest first. Each star's model = its ePSF (evaluated at pixel centres, fitted on the unmasked,
unsaturated wing pixels; skipped when the masked core leaves too few) + a smooth term: a radial profile (medians in
narrow rings of ≥ 40 good pixels, which ignore a real star in the ring) × an angular modulation (medians per sector of
wide rings), to the last ring whose median is ≥ 0.15 × the pixel noise. The local noise factor k ≥ 1 is the robust
scatter of r = 2 px aperture sums of what is left, in polar bins, over the photo's own scatter. Detection (sep, the
guard and the second pass) then runs on IMAGE minus the model with noise × k, outside each star's own pixels (3.5 px; a
saturated core's radius + 1.5 px), which stay as observed. Each modelled star keeps one dot, the detection nearest it
within max(2 px, core radius + 1.5 px), and its aperture flux is measured on IMAGE as before; other detections that
close are pieces of it and dropped. Every other dot is measured on the glow-free image. Files with it live in a folder
with the suffix `_glow` (config.dots_dir_for): the `DOTS_FINE_ZONES` now use `dots_deblend1e-4_cp3_g6_psf_glow/`;
`dots_deblend1e-4_cp3_g6_psf/` stays as written and is read only by a zone whose link recorded it. The sky run (`dots/`)
is unchanged (config `DOTS_SKY_GLOW` false). The stack step (`stack_sources`) does the same at load (each photo block's
glow subtracted, a saturated core's rim too) and scales each S/N map by its own local scatter around bright stars.

**Extraction v2 (16 Nov; docs/extraction-v2.md).** The settings of the one rerun of every photo, off until then: with
`SKYSHIFT_DOTS_V2=1` (config `DOTS_V2`) every zone uses fine detection v2 + the glow model + a matched-filter pass, folder
`dots_deblend1e-4_cp3_g6_psf_glow_v2/`. Nothing in the existing folders changes. The matched-filter pass: the
ePSF-matched filter (inverse-variance weights, the ePSF of the pixel's zone, source centred on the pixel) on the second
pass's residual (IMAGE minus background and the subtracted ePSF models; noise √(noise² + (0.05 · model)²)). Every 3 × 3
local maximum with S/N ≥ 5 (`MF_PASS_SNR`) more than 1 px from every dot, outside the saturation guard and a glow star's
own pixels, and passing the mirror test when it lies within 6 px of a subtracted dot, is a dot with `sep_flag` bit
**0x400**, measured on the residual like 0x200 dots. Its aperture `snr` may be below 5 (matched-filter S/N ≈ 1.5 ×
aperture S/N at S/N 5–7). Rows stay sorted by flux_ujy. v2 files add the columns below (after `flux_ap_err_ujy`), the
peaks file and the v2 photo metadata keys (Photo metadata). Measured on 68 real 256-row bands (ecl04 + hunt, D1–D6):
isolated Gaia stars at aperture S/N 5–5.5 found 33% (sky run) → 85%; known asteroids V 17–18 per photo 16% → 53%;
Gaia pairs 12–15″ split 0% → 95%; negative-image fakes 21 → 65 dots per photo (of ~43,000).

| column (v2 files only) | type | unit | meaning |
|---|---|---|---|
| snr_mf | float32 | | Matched-filter S/N at the dot: the largest over the 3 × 3 pixels around its rounded x, y, of the ePSF-matched filter (centred kernel, one phase) on the image the dot was measured on (IMAGE for a glow star's own dot; IMAGE minus the glow model for other first-pass dots; that minus the subtracted ePSF models for 0x200 and 0x400 dots), minus the background, masked pixels 0, noise the photo's pixel noise (no model term, no block scaling). Never NaN (0 when not finite). Not the session stacks' `snr_mf` (session_stacks, below) |
| n_transient | int8 | | Pixels with FLAGS TRANSIENT (bit 0) within 3 px (at most 127). Weak evidence, never used to reject a dot: TRANSIENT sits beside 11–12% of real asteroids' dots (pixel checks, 16 Nov) |
| n_masked | int8 | | Masked or non-finite pixels (contracts/flags.md mask; from the second pass also the dark holes, below) with centres within 2 px (the aperture), at most 127 |
| partner_flux_ujy | float32 | µJy | r = 2 px aperture on the partner photo's (hole-masked) IMAGE minus its detection background map (no glow or model subtracted, no annulus, no aperture correction: as `flux_ujy`; forced photometry's ePSF fluxes are about 3% higher, its × 1.033) at the dot's sky position (ra_psf, dec_psf where `psf_pos_ok`, else ra, dec) in the simultaneous partner detector's photo (D1↔D4, D2↔D5, D3↔D6, same exposure). | dot_flag | int32 | | **18 Nov.** Why a dot is doubtful or special, one bit per meaning (the bit table under "Extraction v2, 18 Nov fixes"): 0x1 matched-filter dot in the saturation guard, 0x2 failing the mirror test, 0x4 inside a glow star's own pixels, 0x8 matched-filter S/N 4.5–5, 0x10 a saturated core's dot, 0x20 that dot without a flux, 0x40 a matched-filter dot within 2 px of a saturated core's dot, 0x80 (27 Nov) a refused dot whose wings fit was skipped (x, y the matched-filter position). 0 = none. v2 files written before 18 Nov lack it: read as 0 |

**Peaks file (v2)** `<folder>_peaks/<obs_id>D<det>.parquet`, written before the dot file: the matched-filter local
maxima with S/N ≥ 4 (`MF_PEAK_SNR`; **3.5 from 27 Nov**) that are not dots (no dot within 1 px). `x`, `y` float32 (pixel, 0-based), `ra`,
`dec` float64 (deg), `snr_mf` float32, `flux_mf_ujy` float32 (µJy, the matched-filter flux), `flags` int32 (3 × 3 OR),
`n_transient` int8, `why` int8: 0 = S/N 4–5 (from the second pass also a peak ≥ 5 refused by its block's noise scale, below), 1 = refused by the saturation guard, 2 = refused by the mirror test,
3 = inside a glow star's own pixels. From 18 Nov the refused peaks are dots (`dot_flag`), so only why 0 is written,
meaning matched-filter S/N from 4 up to 4.5 (`MF_DOT_LOW_SNR`) × its block's noise scale ("Extraction v2, 18 Nov fixes").

**Extraction v2, second pass (16 Nov evening, v3.26; docs/extraction-v2.md §12).** Still behind `SKYSHIFT_DOTS_V2=1`,
same folder. (1) **Dark holes**: before anything is measured, every 8-connected group of 1–4 unflagged, finite
pixels each more than 5σ below the detection background (σ = max(√VARIANCE, background rms); core
`skyshift_core.holes`, config `DOTS_V2_HOLES`, `HOLE_SIGMA` 5, `HOLE_MIN_PX` 1, `HOLE_MAX_PX` 4, `HOLE_NEAR_BITS` 0,
`HOLE_GROW_PX` 0) is set to NaN in a copy of the photo; every later stage (dots, the second and matched-filter
passes, peaks, forced photometry, the partner image) uses that copy. Mostly cold pixels NASA's COLD bit misses:
300–1,270 per MWIR photo, 2–140 per SWIR photo. Holes count in `n_masked` and are never measured. Only with FLAGS
present. (2) **Matched-filter threshold per detector** (`MF_PASS_SNR_DET`, 5.0 for all six), multiplied per
32 × 32 block (`MF_SIGMA_GRID`) by the S/N map's own σ (median − 15.87th percentile of the block's pixels with data;
a block with under 100 such pixels takes the whole map's) where that σ exceeds 1.1 (`MF_PASS_NORMALISE` "block",
`MF_SIGMA_MIN_SCALE`). (3) A photo with no first-pass dot still gets the matched-filter pass. (4) The saturation
guard's second sep run measures only objects near its candidates (same drops, faster). Measured on 36 photos:
matched-filter fakes per deg² on negative images 9.9–42 → 0.3–2.3, Gaia stars found −0.1 to −1.5%, known asteroids
267 → 265 found. Forced files: a photo whose `forced/` file already exists keeps it (the rule above), so the hole
mask and the red layer (below) reach only forced files written after them.

**Extraction v2, 18 Nov fixes (dot_flag, saturated cores, rejected peaks, extended file, streak file).** Still behind
`SKYSHIFT_DOTS_V2=1`, same folder. Four changes, measured on the bench of 386 photos around known objects
(`scripts/rerun`, reports in `~/skyshift-data/rerun/reports/` on the lead's PC). The lead's rule: a doubtful detection
stays, flagged with why; cuts happen downstream.

1. **Rejected peaks are dots.** A matched-filter peak with S/N ≥ 5 that the saturation guard, the mirror test or a glow
   star's own pixels refused is now a dot too (`sep_flag` 0x400, measured like any matched-filter dot), with one
   `dot_flag` bit per test that refuses it; and matched-filter peaks with S/N 4.5–5 (`MF_DOT_LOW_SNR`, × the block
   scale) are dots with `dot_flag` 0x8. When two measured matched-filter dots converge within 1 px, the one without these
   bits wins (then the brighter). Bench: Rhea 0 → 3 of 8 photos, Titan 4 → 7 of 8, 3I/ATLAS's D3 peaks (refused by the
   mirror test beside a passing star) become dots; known asteroids V < 18 found 741 → 801 of 1,176 (chance 39 → 49);
   dots per photo +29% (crowded fields most: t_barnard +40%).
2. **One dot per saturated core.** Every saturated core that is a star (a masked blob holding OVERFLOW/NONLINEAR,
   masked pixels within 6 px of a saturated one, rim S/N ≥ 50) has exactly one dot (`dot_flag` 0x10), placed by its
   unmasked wings: cores ≤ 3 px radius a Gaussian wings fit, larger ones a power-law profile a(1 + r²)^-β + c, where
   both fail the hole's centre. `pos_err_arcsec` = `pos_err_psf_arcsec` 0.5″ / 0.9″ / 2.0″ by those methods,
   `psf_pos_ok` false, `flux_psf_ujy` the profile's total ÷ its measured per-detector share of the catalogue flux
   (`SAT_CORE_FLUX_SHARE`; ±0.1 dex, D6 ±0.23; D1 uses D2's, unmeasured), `flux_ujy` = that ÷ 1.033, `snr` ≥ the rim's
   brightest pixel S/N, `flags` and `flags_peak` include the core's OVERFLOW/NONLINEAR bits, `psf_chi2_nu` NaN. Without
   a flux (`dot_flag` 0x20) `flux_ujy` and `flux_psf_ujy` are NaN (rows sorted by flux_ujy, NaN last). A matched-filter
   dot within 2 px (`SAT_CORE_DUP_PX`) of a core's dot is kept with `dot_flag` 0x40 added to its own bits: mostly the
   star again (a refused peak in its hole), but it may be a real faint neighbour (a moon, an asteroid passing the
   star); farther out a matched-filter dot keeps only its own bits. Bench: Gaia G < 6 within 3″ 23% → 94%, G 6–8 34% → 96%; R Draconis 0 → 8 of 8, RW Aurigae 5 → 8 of 8,
   Barnard's Star 2 → 7 of 8.
3. **Extended-source file** `<folder>_ext/<obs_id>D<det>.parquet` (below). Dot files are not changed by it.
4. **Streak file** `<folder>_streaks/<obs_id>D<det>.parquet` (below): trails of fast movers. Dot files are not changed
   by it.

`dot_flag` (int32, v2 files written from 18 Nov; after `partner_err_ujy`): why a dot is doubtful or special, one bit
per meaning, bits combine. 0 = a dot the code before 18 Nov kept the same way. Files without the column: read as 0.

| bit | config name | meaning |
|---|---|---|
| 0x1 | DOT_FLAG_MF_GUARD | matched-filter dot within the saturation guard (6 px of an OVERFLOW/NONLINEAR pixel): a saturated star's wings, or something real beside it. Position and flux may be biased by the saturated neighbour |
| 0x2 | DOT_FLAG_MF_MIRROR | matched-filter dot within 6 px of a subtracted (ePSF-modelled) dot that fails the mirror test: a ring or PSF-model error, or a faint source beside a brighter one (3I/ATLAS, faint stars by bright ones). Flux biased by the subtracted neighbour |
| 0x4 | DOT_FLAG_MF_GLOW_PIECE | matched-filter dot inside a glow star's own pixels (max(2 px, core radius + 1.5 px) of a modelled bright star), which the glow model used to drop as a piece of the star: Rhea 10.8 px from Saturn's centre |
| 0x8 | DOT_FLAG_MF_LOW_SNR | matched-filter S/N from 4.5 (`MF_DOT_LOW_SNR`) up to the threshold (5 × the block scale). Honest errors; negative images give 4.2 such dots per deg² |
| 0x10 | DOT_FLAG_SAT_CORE | the one dot of a saturated core, placed by its wings fit (values above) |
| 0x20 | DOT_FLAG_SAT_NOFIT | (with 0x10) the wings fit gave no flux: `flux_ujy`, `flux_psf_ujy` NaN |
| 0x40 | DOT_FLAG_SAT_CORE_DUP | matched-filter dot within 2 px (`SAT_CORE_DUP_PX`) of a saturated core's dot (0x10): mostly the same star a second time (a refused peak in its hole or on its rim; it then carries 0x1/0x2/0x4 too), sometimes a real neighbour (a moon, an asteroid passing the star). Kept, never dropped: cut downstream |
| 0x80 | DOT_FLAG_POS_NOREFIT | **27 Nov.** A refused matched-filter dot (with 0x1, 0x2 or 0x4) with OVERFLOW/NONLINEAR in its 3 × 3 whose wings fit was skipped by the rule `SAT_REFIT_REFUSED_*` (below): `x`, `y`, `ra`, `dec` are the matched-filter position (the other saturated dots are re-centred on their wings). Everything else about the dot is measured as usual at that position |

The bits 0x1–0x8, 0x40 and 0x80 are only ever set on matched-filter dots (`sep_flag` 0x400); 0x10/0x20 on a first-pass dot that
became the core's dot or a row added for it. `sep_flag` (int16) keeps only the meanings it had (sep's 0x1–0x80, 0x200,
0x400, 0x800); no new bit goes there (0x8000 is its sign, the others are taken). The dot set of 16 Nov: rows with
`dot_flag & 0x4F == 0`; the core dots replaced what was then the nearest ring piece. Footer: top-level `dot_flag`
{name: bit} (`mf_guard`, `mf_mirror`, `mf_glow_piece`, `mf_low_snr`, `sat_core`, `sat_nofit`,
`sat_core_dup`, `pos_norefit` from 27 Nov); `mf` adds
`refused_flags` {`guard`, `mirror`, `excluded`: their dot_flag bits; null when refused peaks are not dots},
`low_snr` (4.5), `low_snr_flag` (0x8); `ext` (below); `detect` adds the counts `n_mf_guard`, `n_mf_mirror`,
`n_mf_excluded`, `n_mf_low_snr`, `n_glow_pieces_mf`, `n_sat_cores`, `n_sat_core_dots_new`, `n_sat_core_dots_no_flux`,
`n_sat_core_dots_centre`, `n_sat_core_dup_mf_flagged` (dots given 0x40), and (extended pass) `n_subtracted`, `n_peaks_s2`, `n_peaks_s4`, `n_wide_s2`,
`n_wide_s4`, `n_ext_pass`, `n_ext_s2`, `n_ext_s4`, `n_ext_glow_pieces`; `stages_s` adds
`sat_core_s`, `ext_pass_s` and the streak search's `streaks_s` (total), `streak_maps_s`, `streak_point_s`,
`streak_pieces_s`, `streak_merge_s`, `streak_measure_s`; `streaks` (below).

**Extended-source file (v2, 18 Nov)** `<folder>_ext/<obs_id>D<det>.parquet`, written before the dot file: every peak of
a 2× or 4× PSF-FWHM filter (ePSF ⊗ Gaussian, inverse-variance, on the matched-filter residual with every dot's ePSF
subtracted) with S/N ≥ 5 (× the map's block sigma where > 1.1), seen at ≥ 1.0 × the point filter's S/N, > 1.5 px from
every final dot, outside the saturation guard and the glow stars' reach. Not dots: no step reads it yet. Columns: `x`,
`y` float32 (px), `ra`, `dec` float64 (deg), `snr_ext` float32, `snr_point` float32 (snr_ext / snr_point ≈ 0.76 (2×) /
0.42 (4×) for a star, 1.25 / 2.4 for a source that wide), `ext_scale` int8 (2 or 4), `flux_ext_ujy` float32 (µJy,
total if it has the kernel's shape), `flux_ujy`, `flux_err_ujy` float32 (µJy, r = 2 px on the point-free residual),
`flags` int32 (3 × 3 OR), `near_dot_px` float32. Footer key `ext` in the dot file: `scales`, `min_snr`, `ratio`,
`dedup_px`, `normalise`, `file`, and each map's `sigma_lo`, `median`, `n_neg`. Doubtful by design (bench: ~1,200 rows
per photo, 77% with no catalogue source within 3″; 0.39 per deg² on negative images): cut on `snr_ext` and
`snr_ext / snr_point` (≥ 1.5 keeps ~110 per photo). Env `SKYSHIFT_DOTS_EXT=0`: no file.

**Streak file (v2, 18–20 Nov)** `<folder>_streaks/<obs_id>D<det>.parquet` (pipeline `streaks.py`), written with the
peaks and ext files, before the dot file. Candidate trails of fast movers ≥ 4 px long (≳ 780″/h over the 113.6 s
exposure; 1 px = 6.15″ = 195″/h), found on the matched-filter pass's residual with ePSF trail kernels (4, 6, 9 px × angles
whose ends step 1 px, by FFT, inverse-variance); each length's S/N map normalised by its own scatter in 8 × 8 blocks;
longer trails are chains of collinear pieces fitted as one segment. A row needs `snr_local` ≥ `STREAK_SNR` **4.5** (the
lead's rule, 20 Nov: more fakes rather than miss; 5.5 in the first version: +35% rows); every row keeps `snr` and
`snr_local`, so downstream cuts where it wants. Not written: candidates one point source explains as well
(snr² − snr_point² < 9, or snr_point / snr above 0.8 / 0.75 / 0.7 / 0.65 at 4 / 6 / 9 / ≥ 15 px): stars and blends,
already dots or peaks. One row per streak:

**Extraction v2, 27 Nov (conditions file, stamp file, wings-fit rule, peaks floor, slim switch).** Still behind
`SKYSHIFT_DOTS_V2=1`, same folder; the dot tables are unchanged by the two new files (checked on and off).

1. **Conditions file** `<folder>_cond/<obs_id>D<det>.parquet` (pipeline `cond.py`, config `COND*`, on under v2; env
   `SKYSHIFT_COND=0`: no file), written before the dot file. One row per `COND_TILE_PX` (128) × 128 px tile (256 rows
   for a 2040² photo): what the search met there and what it found. Units: pixels 0-based, degrees, µm, MJy/sr (as
   IMAGE), µJy (point source, the dots' flux scale, no aperture correction); counts are pixels or rows whose position

   | column | type | meaning |
   |---|---|---|

**One dot = one wavelength.** SPHEREx's filter changes wavelength across each detector, so a
photo measures a source at one wavelength per detector. As the telescope re-points, the same
source lands on other parts of the filter; grouping a source's dots by `cell` over a visit gives
its 102-channel spectrum (wavelength_um, bandwidth_um, flux_ujy); `spectra` does this for every
fixed source over all visits (`sources` below). Brightness is `flux_ujy`
(AB magnitude = 23.9 − 2.5 log10 flux_ujy); luminosity needs a distance, so it is computed only
where Gaia gives a parallax, never stored per dot.

Row order is fixed when the file is written (brightest `flux_ujy` first, as core.detect returns
dots) and files are never rewritten: `members.dot_row` points at rows by index (in the zone's folder, above).
Floats are written with byte-stream-split + zstd (Cygnus worst case, 58,725 dots: 6.5 MB).

**Versions.** v3 files (written before 14 Nov evening) have no x_psf, y_psf, ra_psf, dec_psf, pos_err_psf_arcsec,
psf_pos_ok or sep_flag; they are never rewritten. Readers: where the columns exist and `psf_pos_ok` is true, take
ra_psf, dec_psf, pos_err_psf_arcsec as the dot's position; else ra, dec, pos_err_arcsec (with calib's corrections, below).
With a calib.json, a dot takes its ePSF position only if calib.json has an ePSF pos_err model for its detector
(`psf`, schema 3) and that model's calibrated pos_err at the dot's S/N is below the corrected centroid's (pipeline config
`CALIB_PSF_CHOOSE_BY_ERROR`): the ePSF fit has the smaller S/N term, the corrected centroid the smaller floor in most
detectors, so bright dots keep the centroid (36 pilot photos: 78% of Gaia-star dots take the ePSF position; above
S/N ≈ 30–50 the centroid in D1, D2, D4–D6). A calib.json without `psf` (schema 2, or fitted on v3 files) keeps every
dot on the centroid path.
`motion_io.member_dots` says which per dot (`pos_psf` bool) and counts them (stats `pos_psf_dots`, also from `spectra`).
`dots.as_dots` fills missing v4 columns from x, y, ra, dec, pos_err_arcsec (psf_pos_ok false, sep_flag 0).

**Raw vs calibrated values.** A dot file's `ra`, `dec`, `pos_err_arcsec`, `flux_ujy`, `flux_err_ujy`, `flux_psf_ujy`
and `flux_psf_err_ujy` are raw and stay so (files are never rewritten). When `results/<zone>/calib.json` exists, every
step that combines dots (colours, lightcurves, astrometry via the member dots, and spectra) uses the corrected positions
(pixel phase + per-photo distortion), the calibrated `pos_err_arcsec` and the corrected fluxes (flux pixel phase +
per-detector total-flux scale) (`calib` row below); `link` always uses raw positions. Forced photometry is corrected when loaded (`motion_io.load_forced`, used by
lightcurves): PSF fluxes with calib's `forced` factors, aperture fluxes with the dots' factors.
**calib and the ePSF positions (v4):** the pixel-phase correction is for the windowed centroid only. It must **not** be
applied to ra_psf, dec_psf where `psf_pos_ok` is true (the fit has no phase pull: correcting it would add the S-curve
back with the opposite sign); rows with `psf_pos_ok` false carry the centroid and are corrected as before. The per-photo
distortion and the calibrated pos_err should be fitted separately on the ePSF positions (their per-photo offset against
Gaia differs from the centroid's by up to 0.2″: e.g. +0.13″ vs −0.06″ in RA on 2025W43_1A_0679_2D4) and applied to them:
calib.json schema 3 `psf` (calib row below).

sin θ)); `mf` {`min_snr` (the photo's detector's threshold), `peak_snr`, `dedup_px`, `kernel_half_px`, `sep_flag`; second pass (v3.26): `normalise` (`block` | `photo` | `off`), `sigma_lo` and `median` (of the S/N map, 4 decimals, null when not finite), `n_neg` (3 × 3 local minima ≤ −min_snr), `min_snr_used` (the threshold before any block scale; in `photo` mode × max(1, sigma_lo)), `sigma_grid` (32 × 32 block σ, rows = y, block edges as `grids`, 4 significant digits; null only where not finite; v3.27: all null on a photo with too few data pixels to measure, where the threshold keeps its unscaled value)}; `dark_holes` (second pass) {`n_holes`, `n_px`, `depth_min_sigma` (the deepest hole pixel in σ, 0.1 steps, null when none), `config` {`sigma`, `min_px`, `max_px`, `near_bits`, `near_px`, `grow_px`}}; `partner` {`detector`, `obs_id`} when the partner photo filled the partner columns, and
`n_partner` (dots with a partner flux; written in every v2 file, 0 when none); in `detect`, `v2` (true), `mf_pass_snr` (the detector's
threshold), `dark_holes` (bool: the hole mask was configured on, whether or not the photo had FLAGS to apply it) and the counts `n_mf_raw`, `n_mf_pass`, `n_peaks`, `n_peaks_guard`, `n_peaks_mirror`, `n_peaks_excluded`. Older files lack
every one of these: read as absent (no measured noise, depth map, cores or orientation).

Session and visit are one value per photo, from the zone's photo list: a session is a run of the
zone's exposure times with gaps under 10 minutes (`core.sessions`), a visit comes from `core.visits`
on the same times. How many sessions covered a position is counted from the photos' footprints
when a candidate is checked. (Changed 14 Nov after review: per-tile sessions left 3.4% of dots without one.)

**`cell`** (pipeline `sky.cell_of`): `band = floor((dec + 90) × 600)`, `col = floor(ra × cos(dec_band_centre) × 600)`,
`cell = band × 10_000_000 + col` (600 = 3600″ / 6″; `dec_band_centre = (band + 0.5) / 600 − 90`).
An id, not a quantity: the largest is ~1.08 × 10¹², below 2⁵³, so JSON exports (suspects.json) write it
as a plain number. Group with the neighbouring cells too (`sky.neighbour_cells`), so a dot on a cell
edge isn't split; adjacent bands' columns don't line up, so a neighbour in the next band comes from
the position, not from the column number.

## forced: one row per reference target per photo, detected or not

One Parquet file per photo, `forced/<obs_id>D<detector>.parquet`, written before the dot file (so a
dot file still means "photo fully done"), only when a target list exists (else a warning;
the photo is still done). One `forced/` for every folder of dot files: a re-extraction into another folder
(`dots_deblend<value>/`) keeps an existing forced file and writes only a missing one, except extraction v2
(`SKYSHIFT_DOTS_V2=1`, v3.27): it rewrites an existing forced file (forced photometry on the hole-masked image, with
the red layer's targets; run stats `forced_replaced`), so the one rerun leaves no sky-run forced file behind. Target list: the sky-wide list `refcat/sky/forced_n32/` when it is complete
(its `_complete.json` exists), else `refcat/<zone>_forced.parquet` as before. Targets: the list's rows moved
to the photo's MJD-AVG by proper motion only (core.propagate; NaN proper motion = 0; parallax ignored), kept
if ≥ 3 px inside the frame and, with the zone list only, inside the zone box + 0.05° (the sky list has no zone
box: every target in the photo's footprint, whatever zone it was extracted under). Negative and low fluxes
are kept: they are the non-detections.

**Sky-wide list (added 14 Nov)**, written by `python -m skyshift_pipeline.forced_sky`: one file per nested
HEALPix pixel at nside 32, `refcat/sky/forced_n32/p<pixel:05d>.parquet` (12,288 files, 3.357 deg² each), with
exactly the columns of `refcat/<zone>_forced.parquet` (below), sorted by G. A Gaia source sits in the pixel of
its source_id (`source_id >> 49`, the level-12 HEALPix index in the id taken to nside 32); dots reads every
pixel within the photo's cone (half diagonal + 0.1° + 0.05°). Content: Gaia DR3 G < 17.5 (no CatWISE-only

`gaia_g_max`, `max_per_deg2` (null = no cap), `cap_per_partition`, `catalogues`, `rows`, `capped_partitions`,

**Red layer (16 Nov second pass, v3.26)**, written by `python -m skyshift_pipeline.forced_sky --red`:
