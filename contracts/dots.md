# contracts/dots.md: the dot table, forced photometry and derived tables (v4)

Owner: P1. Written by pipeline/, read by validation scripts and the suspects export.
Units: degrees, arcsec, µm, µJy, MJD (UTC).

## dots: one row per detected point in one photo

One Parquet file per photo in `gs://nasa-glazing-data/dots/`. Its existence marks the photo done;
skip it on restart. No job list, no locks, no tiles.
File name `dots/<obs_id>D<detector>.parquet`, e.g. `dots/2025W18_1B_0074_2D1.parquet`.

| column | type | unit | meaning |
|---|---|---|---|
| obs_id | string | | IRSA observation id, e.g. `2025W18_1B_0074_2` |
| detector | int8 | | 1–6, from `energy_bandpassname` or the IMAGE header `DETECTOR`, never the file name |
| mjd | float64 | MJD | MJD-AVG of the exposure (UTC midpoint) |
| session | int32 | | From the visit rule (contracts/api.md), per position; 1 = earliest |
| visit | int16 | | From the visit rule, per position; 1 = earliest |
| ra, dec | float64 | deg | Sky position, ICRS, as measured (no proper-motion correction). Raw: pulled up to ~0.1 px towards the pixel centre (windowed centroid); derived tables use `calib`'s corrected positions |
| pos_err_arcsec | float32 | arcsec | 1σ position error per axis: `sqrt((1.4 × 3.2″ / snr)² + 0.25″²)`. 3.2″ is the PSF's σ (FWHM 7.53″); 0.25″ is the floor measured against Gaia on the first photo, to be replaced by V3's value. Raw, as written: 1.4–1.8× too small against Gaia (pilot); derived tables use the `calib` value |
| x, y | float32 | pixel | Position in the exposure, 0-based (numpy) |
| flux_ujy | float32 | µJy | Brightness (IMAGE MJy/sr × 889 µJy per 6.15″ pixel, summed in the aperture) |
| flux_err_ujy | float32 | µJy | Brightness error |
| wavelength_um | float32 | µm | Wavelength at that pixel, from WCS-WAVE |
| bandwidth_um | float32 | µm | Bandwidth at that pixel, from WCS-WAVE (one of the 102 channels' width) |
| elong | float32 | | Elongation a/b of the detected shape (sep). Near 1 for stars; large for trails, streaks and cosmic-ray hits |
| snr | float32 | | Signal-to-noise. Detection runs at `thresh=2.0` (about S/N 9 for a point source); only dots with snr ≥ 5 are kept |
| flags | int32 | | OR of the flag bits in the 3×3 pixels around the dot, including recorded ones (contracts/flags.md) |
| flags_peak | int32 | | Flag bits at the dot's peak pixel. SOURCE here means a catalogued star or compact galaxy (to AB 19); used only to filter suspects |
| cell | int64 | | 6″ sky cell id (no unit), used to group dots by position; rule below |
| zodi_mjysr | float32 | MJy/sr | ZODI model (zodiacal light) at the dot's pixel. IMAGE is **not** zodi-subtracted (Expsupp 2.2, 3.2.11); NaN if the file has no ZODI |
| bkg_mjysr | float32 | MJy/sr | Background map core.detect subtracted (sep, 32 px mesh) at the dot's pixel; includes zodi and any diffuse light |
| peak_mjysr | float32 | MJy/sr | Peak pixel above that background (sep `peak`) |
| a_arcsec, b_arcsec | float32 | arcsec | √ of the eigenvalues of the intensity-weighted second moments (good pixels within 2.5 px, local annulus 3.5–5.5 px subtracted). A star gives a ≈ b ≈ 3.5–5″ (the window truncates and the PSF is undersampled: a relative measure). NaN as for elong |
| theta_deg | float32 | deg | Major-axis angle in pixel coordinates, from +x towards +y, in (−90, 90]. `elong = a_arcsec / b_arcsec` (capped at 99) |
| flux_psf_ujy | float32 | µJy | Total flux from a fit of the photo's ePSF (EPSF HDU, zone containing the dot) at the dot's fixed (x, y) plus a local constant, on 7 × 7 pixels, masked pixels left out. Weights 1/(max(√VARIANCE, background rms)² + (0.03 · model)²). Total flux, so `flux_psf_ujy / flux_ujy` is the r = 2 px aperture correction (ePSF: 1.033). NaN with fewer than 12 good pixels or no EPSF HDU |
| flux_psf_err_ujy | float32 | µJy | 1σ of flux_psf_ujy from the fit (no extra systematic term) |
| psf_chi2_nu | float32 | | χ²/(n − 2) of that fit. Compare at a given S/N: star-like dots sit near 2–3 at S/N 5–10 and rise with S/N (centroid error at fixed position and the ePSF's own error: median 20–30 at S/N > 100 on the Cygnus photo); galaxies, blends and artefacts sit well above the star locus |
| x_psf, y_psf | float32 | pixel | **v4.** Position from a fit of the photo's ePSF for x, y, flux and a local constant (Gauss–Newton from the windowed centroid; same 7 × 7 stamp, mask, weights and model term as flux_psf_ujy; Anderson & King's method for undersampled data). It has no pixel-phase pull: on 6 pilot photos (one per detector) the windowed centroid's S-curve of 0.05–0.11 px became 0.01–0.02 px. Where the fit didn't run or failed (`psf_pos_ok` false) these are x, y: the windowed or, saturated, the wings centroid |
| ra_psf, dec_psf | float64 | deg | **v4.** x_psf, y_psf through the same WCS as ra, dec (ICRS, as measured). Per-axis scatter against Gaia, S/N ≥ 5, per photo's offset removed: D1–D3 0.20–0.26″ (centroid 0.41–0.69″), D4–D6 0.26–0.31″ (0.38–0.47″); 0.10–0.18″ at S/N 50–300 |
| pos_err_psf_arcsec | float32 | arcsec | **v4.** 1σ per axis of ra_psf, dec_psf: the fit's covariance, √((σx² + σy²)/2) × 6.152″, in quadrature with 0.13″ (config `PSF_POS_ERR_FLOOR_ARCSEC`; robust pull scatter against Gaia then 0.8–1.2 per detector and axis, S/N ≥ 5). pos_err_arcsec where `psf_pos_ok` is false |
| psf_pos_ok | bool | | **v4.** True where x_psf … pos_err_psf_arcsec come from the ePSF fit: it ran (EPSF HDU present, config `DOTS_PSF_POSITION`, not saturated (no OVERFLOW/NONLINEAR in the 3×3), snr ≥ `PSF_POS_MIN_SNR` = 5, ≥ 12 good pixels), converged within 10 steps, F > 0, ended ≤ 1 px from the centroid. Pilot photos: 98–99% of unsaturated dots, 99.9% of Gaia-matched ones |
| sep_flag | int16 | | **v4.** sep's extraction flags from core.detect (sep.extract `flag`): 1 = blended (deblended from a neighbour), 2 = truncated (touches the edge or a masked area), 4/8 = pixel-stack or singular-moment trouble. For vetting; 5–26% of dots on the pilot photos have one set |
| flux_ap_ujy | fixed_size_list&lt;float32&gt;[5] | µJy | Aperture fluxes at radii 1.0, 1.5, 2.0, 3.0, 4.5 px (config `AP_RADII_PX`, also in the photo metadata), background = mean of the 5.5–8 px annulus around the dot, masked pixels left out |
| flux_ap_err_ujy | fixed_size_list&lt;float32&gt;[5] | µJy | Their errors (noise max(√VARIANCE, background rms), incl. the annulus' error) |

**One dot = one wavelength.** SPHEREx's filter changes wavelength across each detector, so a
photo measures a source at one wavelength per detector. As the telescope re-points, the same
source lands on other parts of the filter; grouping a source's dots by `cell` over a visit gives
its 102-channel spectrum (wavelength_um, bandwidth_um, flux_ujy); `spectra` does this for every
fixed source over all visits (`sources` below). Brightness is `flux_ujy`
(AB magnitude = 23.9 − 2.5 log10 flux_ujy); luminosity needs a distance, so it is computed only
where Gaia gives a parallax, never stored per dot.

Row order is fixed when the file is written (brightest `flux_ujy` first, as core.detect returns
dots) and files are never rewritten: `members.dot_row` points at rows by index.
Floats are written with byte-stream-split + zstd (Cygnus worst case, 58,725 dots: 6.5 MB).

**Versions.** v3 files (written before 14 Nov evening) have no x_psf, y_psf, ra_psf, dec_psf, pos_err_psf_arcsec,
psf_pos_ok or sep_flag; they are never rewritten. Readers: where the columns exist and `psf_pos_ok` is true, take
ra_psf, dec_psf, pos_err_psf_arcsec as the dot's position; else ra, dec, pos_err_arcsec (with calib's corrections, below).
With a calib.json, a dot takes its ePSF position only if calib.json has an ePSF pos_err model for its detector
(`psf`, schema 3) and that model's calibrated pos_err at the dot's S/N is below the corrected centroid's (pipeline config
`CALIB_PSF_CHOOSE_BY_ERROR`): the ePSF fit has the smaller S/N term, the corrected centroid the smaller floor in most
detectors, so bright dots keep the centroid (36 pilot photos: 78% of Gaia-star dots take the ePSF position; above
S/N ≈ 30–50 the centroid in D1, D2, D4–D6). A calib.json without `psf` (schema 2, or fitted on v3 files) keeps every
dot on the centroid path.
`motion_io.member_dots` says which per dot (`pos_psf` bool) and counts them (stats `pos_psf_dots`, also from `spectra`).
`dots.as_dots` fills missing v4 columns from x, y, ra, dec, pos_err_arcsec (psf_pos_ok false, sep_flag 0).

**Raw vs calibrated values.** A dot file's `ra`, `dec`, `pos_err_arcsec`, `flux_ujy`, `flux_err_ujy`, `flux_psf_ujy`
and `flux_psf_err_ujy` are raw and stay so (files are never rewritten). When `results/<zone>/calib.json` exists, every
step that combines dots (colours, lightcurves, astrometry via the member dots, and spectra) uses the corrected positions
(pixel phase + per-photo distortion), the calibrated `pos_err_arcsec` and the corrected fluxes (flux pixel phase +
per-detector total-flux scale) (`calib` row below); `link` always uses raw positions. Forced photometry is corrected when loaded (`motion_io.load_forced`, used by
lightcurves): PSF fluxes with calib's `forced` factors, aperture fluxes with the dots' factors.
**calib and the ePSF positions (v4):** the pixel-phase correction is for the windowed centroid only. It must **not** be
applied to ra_psf, dec_psf where `psf_pos_ok` is true (the fit has no phase pull: correcting it would add the S-curve
back with the opposite sign); rows with `psf_pos_ok` false carry the centroid and are corrected as before. The per-photo
distortion and the calibrated pos_err should be fitted separately on the ePSF positions (their per-photo offset against
Gaia differs from the centroid's by up to 0.2″: e.g. +0.13″ vs −0.06″ in RA on 2025W43_1A_0679_2D4) and applied to them:
calib.json schema 3 `psf` (calib row below).

**Photo metadata.** Every dot file (empty ones too) carries one JSON object in the Parquet
key-value metadata under the key `skyshift_photo` (read it with `skyshift_pipeline.dots.photo_meta(path)`):
`schema` (1), `obs_id`, `detector`, `status` (`done` | `done_finast`), `pipeline_version` (PRIMARY `VERSION`),
`epsf_calib` (ePSF calibration id from the IMAGE HISTORY), `n_dots`, `n_forced` (null without a refcat),
`read_s`, `detect_s`, `forced_s`, `stages_s` (seconds per stage), `zodi_median_mjysr`, `bkg_median_mjysr`,
`ujy_per_mjysr`, `aperture_radii_px`, `aperture_bkg_annulus_px`, `psf_fit` (`half_px`, `model_frac`, `noise`; v4 also
`position` (true if x_psf … were fitted), `pos_min_snr`, `pos_err_floor_arcsec`),
`header` (IMAGE header values as written by IRSA, null when absent: MJD-BEG/AVG/END, XPOSURE, TELAPSE;
spacecraft geocentric position X_SC/Y_SC/Z_SC [km] and velocity VX_SC/VY_SC/VZ_SC [km/s] at mid, plus
`_START` and `_END`; FINAST, MATCH_NSTARS, ASTRONETSOLVED, OMEGA_MEDIAN/OMEGA_STDDEV [arcsec²], PSF_FWHM [″],
L1DQAFLG, L2DQAFLG, HE_AG_AMPL, AURORA_CORR, SHUTTLE_GLOW_CORR, NBLMSRCS, NSNOWSRC, `L2 SATSTRKS`, SPS_ELON,
SPS_ELAT, SPS_EPA [deg], SGT_MIN_GCD2SAA [deg], and every `L2 N_*` flag count),
`calibration` (`astrometry_vs_gaia`: n, median `dra_cosdec_arcsec` and `ddec_arcsec` of dot − Gaia,
`sigma_ra_arcsec`/`sigma_dec_arcsec` = 1.4826 × MAD, for dots with snr > 20 within 2″ of a forced `gaia:`
target; `psf_moments`: n, median `fwhm_arcsec` = 2.3548 √(a b), `ellipticity` = 1 − b/a, `theta_deg`, from
unsaturated dots with snr > 50; `psf_over_aperture_flux`: median flux_psf_ujy / flux_ujy of the same dots),
`grids` (`n` = 32, `bkg_mjysr` and `zodi_mjysr`: 32 × 32 block means, rows = y, block edges
round(linspace(0, 2040, 33)), MJy/sr, 5 significant digits; null if absent). NaN is written as null.

Session and visit are one value per photo, from the zone's photo list: a session is a run of the
zone's exposure times with gaps under 10 minutes (`core.sessions`), a visit comes from `core.visits`
on the same times. How many sessions covered a position is counted from the photos' footprints
when a candidate is checked. (Changed 14 Nov after review: per-tile sessions left 3.4% of dots without one.)

**`cell`** (pipeline `sky.cell_of`): `band = floor((dec + 90) × 600)`, `col = floor(ra × cos(dec_band_centre) × 600)`,
`cell = band × 10_000_000 + col` (600 = 3600″ / 6″; `dec_band_centre = (band + 0.5) / 600 − 90`).
An id, not a quantity: the largest is ~1.08 × 10¹², below 2⁵³, so JSON exports (suspects.json) write it
as a plain number. Group with the neighbouring cells too (`sky.neighbour_cells`), so a dot on a cell
edge isn't split; adjacent bands' columns don't line up, so a neighbour in the next band comes from
the position, not from the column number.

## forced: one row per reference target per photo, detected or not

One Parquet file per photo, `forced/<obs_id>D<detector>.parquet`, written before the dot file (so a
dot file still means "photo fully done"), only when a target list exists (else a warning;
the photo is still done). Target list: the sky-wide list `refcat/sky/forced_n32/` when it is complete
(its `_complete.json` exists), else `refcat/<zone>_forced.parquet` as before. Targets: the list's rows moved
to the photo's MJD-AVG by proper motion only (core.propagate; NaN proper motion = 0; parallax ignored), kept
if ≥ 3 px inside the frame and, with the zone list only, inside the zone box + 0.05° (the sky list has no zone
box: every target in the photo's footprint, whatever zone it was extracted under). Negative and low fluxes
are kept: they are the non-detections.

**Sky-wide list (added 14 Nov)**, written by `python -m skyshift_pipeline.forced_sky`: one file per nested
HEALPix pixel at nside 32, `refcat/sky/forced_n32/p<pixel:05d>.parquet` (12,288 files, 3.357 deg² each), with
exactly the columns of `refcat/<zone>_forced.parquet` (below), sorted by G. A Gaia source sits in the pixel of
its source_id (`source_id >> 49`, the level-12 HEALPix index in the id taken to nside 32); dots reads every
pixel within the photo's cone (half diagonal + 0.1° + 0.05°). Content: Gaia DR3 G < 17.5 (no CatWISE-only
objects yet); each pixel keeps at most its brightest 8,221 (= 30,000 per 3.5° photo, 2,449/deg²), so the
galactic plane gets a brighter G limit per pixel. `_complete.json` (written last): `nside`, `order`,
`gaia_g_max`, `max_per_deg2` (null = no cap), `cap_per_partition`, `catalogues`, `rows`, `capped_partitions`,
`rows_per_partition` (12,288 ints), `built`.

| column | type | unit | meaning |
|---|---|---|---|
| obs_id, detector, mjd | string, int8, float64 | , , MJD | As in dots |
| ref_id | string | | From the refcat, e.g. `gaia:4472832130942575872`, `catwise:J…` |
| ra, dec | float64 | deg | Target position at the photo's MJD-AVG |
| x, y | float32 | pixel | Its 0-based pixel position (full WCS incl. SIP) |
| flux_psf_ujy, flux_psf_err_ujy, psf_chi2_nu | float32 | µJy, µJy, | ePSF fit at the fixed (x, y), as in dots |
| flux_ap2_ujy, flux_ap2_err_ujy | float32 | µJy | r = 2 px aperture on IMAGE minus the detection background map: the same measure as a dot's `flux_ujy` |
| wavelength_um, bandwidth_um | float32 | µm | From WCS-WAVE at (x, y) |
| zodi_mjysr, bkg_mjysr | float32 | MJy/sr | As in dots |
| flags | int32 | | OR of the flag bits in the 3×3 pixels at the target |

## Derived tables (in `gs://nasa-glazing-data/results/`)

| table | rule |
|---|---|
| fixed | Dots within 4″ of each other seen in 3 or more sessions (stars, galaxies) |
| movers | Not within 6″ of a fixed source; paired inside one session (≤ 3″ + 1″/min × Δt between exposures) or by 2 detectors exposed at the same moment (D1+D4, D2+D5, D3+D6); position covered by ≥ 3 sessions. Only fixed sources veto; a stray single dot elsewhere doesn't. Added 14 Nov (vetting): each mover's dots as lists in time order, `dot_obs` list<string> (obs_id), `dot_det` list<int8>, `dot_x`, `dot_y` list<float32> (pixel, 0-based), `dot_mjd` list<float64>, `dot_flux`, `dot_snr` list<float32>, `dot_size` list<float32> (√(a_arcsec·b_arcsec), arcsec), `dot_chi2` list<float32> (psf_chi2_nu), `dot_fpk` list<int32> (flags_peak), `dot_row` list<int32> (row in the dot file; −1 unknown). NaN where a dot file lacks the column |
| freedots | `results/<zone>/freedots.parquet`, written by `link` (tiles: owned by position, merged): one row per free dot (not in or within 6″ of a fixed source, elong ≤ 3: the dots movers are paired from). `obs_id` string, `detector` int8, `x`, `y` float32 (pixel), `ra`, `dec` float64. Sorted by obs_id, detector, x, y. For the suspects' hot-pixel and bad-column maps |
| nonfixed_dots | `results/<zone>/nonfixed_dots.parquet`, written by `link` (tiles: owned by the dot's position, merged like movers; added 14 Nov): one row per dot inside the zone in no fixed group with elong ≤ 3, the movers' own dots included. `ra`, `dec` float64 (deg), `mjd` float64 (MJD-AVG), `session` int32, `visit` int16, `obs_id` string, `detector` int8, `dot_row` int32 (0-based row in `dots/<obs_id>D<detector>.parquet` as written), `snr` float32, `flux_ujy` float32 (µJy), `flags`, `flags_peak` int32 (the dot's 32 bits, contracts/flags.md), `elong` float32, `near_fixed` bool (within 6″ of a fixed source: link's veto zone, still not in its group). Sorted by session, mjd, ra, dec. Hunt ~0.8 M rows, ~20 MB. Read by `tracklets` to recover a track's missed sightings. Not freedots (that one has pixel x, y and no near-fixed dots). When link can't build it, link still finishes and the file is not written; tracklets then links without recovery |
| tracklets | `results/<zone>/tracklets.parquet`, written by `tracklets` (zone level after link, before score; tiles: once on the merged movers; added 14 Nov): one row per mover. A track = movers of ≥ 3 sessions of one visit (exactly 3: within 36 h) at 0.5–150″/h; tracks never cross visits. `mover_id` string (= suspects' `id`, `<zone>-<cell>-<round(mjd × 1440)>`), `session` int32, `visit` int16, `mjd` float64 (MJD), `ra`, `dec` float64 (deg; the mover's), `cell` int64, `tracklet_id` int64 (unique in the zone; −1 = on no track), `n_sessions` int16 (sessions with a mover on the track; 1 off a track), `n_movers` int16 (movers on the track; 1 off a track), `n_recovered_sessions` int16 (other sessions where tracklet_dots has dots of the track; 0 off a track), `span_h` float32 (hours, first to last mover), `rate_arcsec_h` float32 (″/h, from the local fit at this mover's time), `pa_deg` float32 (direction of motion, degrees east of north, 0–360), `rate_sigma` float32 (″/h, 1σ of the rate, × √χ²_ν where χ²_ν > 1), `rate_snr` float32 (rate_arcsec_h / rate_sigma), `vra_arcsec_h`, `vdec_arcsec_h` float32 (″/h east and north on the plane tangent at the track's median position), `fit_chi2_nu` float32 (the local fit), `track_chi2_nu` float32 (the whole track, leave-one-out), `resid_arcsec` float32 (″, this mover from its local fit), `fit_degree` int8 (1 = linear plus the visit's acceleration, 2 = quadratic; 0 off a track). Float columns are NaN off a track (thresholds and the error model: pipeline config `TRACK_*`). If the step fails, it writes both tables empty (no rows); score then counts movers only |
| tracklet_dots | `results/<zone>/tracklet_dots.parquet`, written by `tracklets` (added 14 Nov): one row per recovered dot, i.e. a nonfixed_dots dot in another session of the track's visit (up to 60 h before its first or after its last mover) within the match radius (3–8″) of the track's predicted position at the dot's own time. `tracklet_id` int64, `visit` int16, `session` int32, `obs_id` string, `detector` int8, `dot_row` int32, `ra`, `dec`, `mjd` float64, `snr`, `flux_ujy` float32 (µJy), `flags`, `flags_peak` int32 (as nonfixed_dots), `sep_arcsec` float32 (″ from the prediction), `r_arcsec` float32 (″, the match radius used), `pred_ra`, `pred_dec` float64 (deg, predicted position at `mjd`). Sorted by tracklet_id, mjd, ra, dec. score counts a known sighting found when a mover or one of these dots matches it (recall below) |
| recall | `results/<zone>/recall.json` and `recall_units.parquet`, written by `score` (gate G2). Unit: one known object (MPC) in one session, predicted inside ≥ 2 exposures, at least `edge_px` from the edge and inside the zone. Found: a mover of that session, or (since 14 Nov) a tracklet_dots dot of that session, within `match_arcsec` (12″) of the prediction moved to its time; `found_by` says so in words. Top level, V < `v_max` (16): `n_known`, `n_found`, `recall` (n_found / n_known: movers or recovered dots), `n_found_movers`, `recall_movers` (movers alone, the measure before tracklets), `dot_share` (any dot within 12″ in one of the unit's photos), `control_recall` (each unit moved `control_offset_arcsec` in a random direction, seed `control_seed`; movers or recovered dots), `control_recall_movers` (the control, movers alone), `control_dot_share`, `g2_threshold`, `g2_pass` (recall ≥ g2_threshold), `recovered_dots` (rows in tracklet_dots), `photos_with_predictions`, `unit`. `per_object` (an object found in any of its sessions), `v_12_to_16`, `v_lt_12_saturated` and each `by_v` bin (`v_min`, `v_max`) hold `n`, `found`, `recall`, `found_movers`, `recall_movers`, `dot_share`, `control_recall`, `control_recall_movers`, `control_dot_share`. Fractions are 0–1, null when n = 0. A file without `recall_movers` (written before tracklets) counted movers only in `recall`. `recall_units.parquet`: one row per unit, `unit`, `name`, `number`, `v`, `session`, `mjd`, `n_photos` and the booleans `mover`, `recovered`, `found` (mover or recovered), `dot` and their `ctl_*` twins |
| members | `results/<zone>/members.parquet`, written by `link`: one row per dot of a fixed source. `source_id` int64, `obs_id` string, `detector` int8, `dot_row` int32 (0-based row in `dots/<obs_id>D<detector>.parquet` as written; dot files are never rewritten). Sorted by source_id, obs_id, detector, dot_row. `fixed` also carries `source_id` (= 6″ `cell` × 100 + rank of the source in its cell by RA, Dec) |
| sources | `results/<zone>/sources.parquet`, written by `spectra`: one row per fixed source. `source_id` int64, `ra`, `dec` float64 (median of its dots), `pos_err_arcsec` float32 (dot scatter / √n per axis, floor 0.05″), `n_dots` int32, `n_sessions` int16, `n_visits` int16, `detectors` int8 (bit d−1 set if seen by detector d), `cell` int64, `saturated` bool (≥ 2 dots with OVERFLOW/NONLINEAR in their 3×3), `flux_ujy` fixed_size_list<float32>[102] (NaN where empty), `err_ujy` fixed_size_list<float32>[102], `n` fixed_size_list<int16>[102] (dots used), `chi2_nu` float32 (kept dots against their channel values; ≈ 1 constant, ≫ 1 variable or bad errors), `visit_flux_ratio` float32 (last visit / first visit: per detector the median of flux ÷ channel value; median over detectors; NaN with one visit), `variable` bool (chi2_nu > 5 and ratio beyond ×/÷ 1.25). Per channel: dots with MASK bits (contracts/flags.md) in their 3×3 left out; gross outliers clipped (> 5 × max(error, MAD) and > 1.5 × |median| from the median); inverse-variance weighted mean, error 1/√Σw × √max(1, χ²/(n−1)) |
