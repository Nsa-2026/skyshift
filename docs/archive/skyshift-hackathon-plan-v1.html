The idea

Three proven tools, combined into one

Each part already works somewhere else. Nobody has put them together for SPHEREx.

Borrowed from WiseView

Blink like an astronomer

Real SPHEREx photos of one patch, one frame per sky pass, played as a loop. Anything that moves jumps; anything that changes flickers.

Our pipeline lists suspects: dots that moved or match no known star. Visitors vote real, junk or not sure, and the votes are saved.

How SPHEREx sees

102 colours from a camera with a rainbow filter

SPHEREx doesn't take one colour photo. Each of its six detectors sits behind a filter whose colour changes from one side to the other in 17 steps. As the telescope steps across the sky, every spot slides through all 17 steps of all 6 detectors. That gives 102 brightness measurements, one per colour, every six months. Lined up, they form a spectrum: a fingerprint of what the object is made of.

1 · Six clean colour channels for blinking

Inside one sky pass we add together every photo from the same detector. That gives 6 sharp, low-noise pictures per pass, the trick NASA suggested. The blink movie compares the same detector across passes.

2 · A spectrum on the fly

Each photo knows which colour every pixel saw (a small wavelength map inside the file). Collect an object's brightness from all its photos, sort by colour, and you have its 102-point spectrum.

3 · False-colour pictures

Paint detector 1 blue, detector 3 green and detector 6 red. Ordinary stars come out white. Cold brown dwarfs and dusty objects come out red and jump out of the picture.

4 · Fair comparisons only

One spot is seen in a different colour in every photo, so brightness changes between raw photos are mostly colour, not real flicker. We only compare the same detector and nearby colours across time.

Technology

How a photo becomes a dot in our database

This is the deep-zone pipeline. It never stores photos: it reads one, measures it, saves the measurements and throws the photo away.

Fetch only what we need

Each photo file is 65 MB in 6 parts. We read only the picture, the quality flags and the wavelength map: about 28 MB.

Mask the junk

The flags mark cosmic-ray hits, satellite trails, reflections and leftover glow. Flagged pixels never become dots.

Find the dots

The sep library finds every point of light and measures its position and brightness.

Tag each dot

Convert pixel to sky position, and record the time and the colour that pixel saw.

Save to the table

Write Parquet files and query them with DuckDB, which handles billions of rows on one computer.

Link across time

Group dots that are the same object within one pass, then follow them between passes.

Check what's known

Match against Gaia DR3 stars and known asteroid positions for each photo's date.

Rank suspects

Dots that moved, have no match, or look unusually red go to the top of the suspect list.

Outside the deep zone: on demand

When someone opens a spot, the server asks NASA's archive which photos cover it, downloads small cutouts instead of whole files, aligns them, groups them by detector and pass, adds each group together and sends back PNG frames. Results are cached, and the five test objects are prepared in advance so the demo is instant.

The data contract (agree in hour one)

Frontend and backend build in parallel against these shapes. Fake data first, real data later.

Server

  • Python with FastAPI
  • astroquery to find photos in NASA's archive (IRSA)
  • astropy and reproject to read, align and stack photos
  • IRSA cutout service for small downloads
  • Votes in Firestore or SQLite

Deep-zone pipeline

  • sep for dot finding, astropy for sky positions
  • HEALPix tiles to split the sky into equal chunks
  • DuckDB + Parquet for the dot table
  • Gaia DR3 and SkyBoT (known asteroids) for matching
  • A job list so many machines can share the work

Scale-up path

Start small, grow only when the last step works

Aladin's ready-made picture covers the whole sky from the start, so the product is complete even if we only rebuild 5% in depth. Each phase starts only when the one before it works.

Phase A · Day 1 afternoon

The five test fields

A small patch around each NASA test object: a few hundred photos each. Runs on any laptop in minutes.

Proves: the pipeline finds Barnard's Star moving and R Draconis pulsing.

Gate: all five show the expected motion or change.

Phase B · Day 1 night

5% of the sky

About 2,000 square degrees, for example right ascension 7h–10h and declination −15° to +25°. That patch crosses the plane of the planets (lots of asteroids to test on) and contains WISE 0855.

Size: ~65,000 photos, ~1.8 TB streamed and deleted, tens of GB kept. About 2 hours on one 64-core Google Cloud machine next to the data. The home desktop is the backup.

Gate: suspect list loaded and "we re-found N known asteroids" measured by Day 2 morning.

Phase C · only if time allows

The whole sky

~1.3 million photos, ~37 TB streamed. On the same cloud machine: roughly 15–20 hours, well inside the €264 Google credit.

Fallback: run one hour in the cloud, measure the speed and cost, and present the full-sky projection to the judges.

Gate: Phase B done and cloud quota approved.

Risks

What can go wrong, and the backup

NASA's archive is slow on demo day

Pre-cache the five targets and the demo patch on the presenting laptop.

Name lookup service is down

It happened while we planned: the Strasbourg (CDS) service returned errors. Keep a built-in list and load Aladin from a package CDN, with sky tiles from NASA's servers.

Venue Wi-Fi is slow

Heavy downloads run on the cloud machine next to the data. Laptops only hold code and a local copy of demo data.

Too many false alarms

Use the quality flags, require a dot in at least two photos per pass, match Gaia and asteroids, then let votes sort the rest.

Google stops the cheap cloud machine

Spot machines can be reclaimed. The job list remembers finished batches, so a restart continues where it stopped.

Too many features, nothing finished

Core features first, fixed feature freeze on Day 2 afternoon, stretch features only after that if time is left.
